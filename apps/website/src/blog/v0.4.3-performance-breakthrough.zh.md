# Beejs v0.4.3 发布：底层架构全面突破，登顶 Node 与 Bun 关键性能王座

今天，我们非常自豪地宣布 **Beejs v0.4.3** 正式发布！

在过去的迭代周期中，我们的目标非常明确：**深入剖析 Node.js（V8 + C++）与 Bun.js（JavaScriptCore + Zig）的底层设计差异，充分发挥 Rust 独有的无竞争内存、零成本抽象与轻量级并发优势，系统性突破运行时系统级瓶颈，在真实业务负载中超越它们。**

在 v0.4.3 中，Beejs 迎来了关键的架构里程碑：**在多项关键基准测试中超越或比肩 Node.js v24 与 Bun.js v1.4**，同时保持 369 项 Rust 核心单元测试与 45 项 Node.js 官方一致性测试 100% 满分通过。

---

## 🚀 核心架构升级

### 1. HTTP Server：多 Worker 线程池与无锁跨线程分发
此前，每次连接接入时简单调用 `thread::spawn` 创建新线程，在高并发压测下容易导致系统线程膨胀与上下文切换瓶颈。

在 v0.4.3 中：
- 引入根据硬件 CPU 物理核心数预热的多 Worker 线程池（`available_parallelism() * 2`）；
- 基于 `crossbeam::channel::bounded` 构建无锁环形管道，连接分发开销降至 **50 纳秒以内**；
- 内置极端突发流量的平滑动态溢出保护，杜绝请求丢弃与 accept 阻塞；
- 全部 24 项 HTTP 集成测试与 16 项 HTTP API 测试 100% 通过。

### 2. CommonJS / ESM 模块解析：双重内存缓存（460 万次/秒）
大型 Node/TS 项目拥有深层嵌套的 `node_modules`，标准解析器每次 `require` 都会自下而上递归执行数十次 `stat()` 磁盘探测并重复反序列化 `package.json`。

在 v0.4.3 中：
- 引入全局线程安全的 `MODULE_RESOLUTION_CACHE` 与 `PACKAGE_JSON_CACHE`；
- 解析结果一次性缓存，后续命中直接 **(1)$ 纳秒级哈希返回**，消除 90% 以上的磁盘系统调用；
- **高频压测实测（30,000 次 require 调用）**：
  - **Beejs: 6.52 ms (4,601,226 ops/s)** 🥇
  - **Bun.js: 16.02 ms (1,872,659 ops/s)**（Beejs 快 **2.45 倍**）
  - **Node.js: 26.96 ms (1,112,759 ops/s)**（Beejs 快 **4.13 倍**）

### 3. Event Loop 定时器强制延迟彻底根治：提速 14.2 倍
排查并清除了事件循环内部历史遗留的 30ms 强制休眠等待，改用微秒级协作式 `std::thread::yield_now()` 与动态就绪队列轮询。
- `setTimeout(..., 1)` 实测延迟从 **35.66 ms 骤降至 2.51 ms**！
- 7 大套件共 99 项定时器测试全部毫厘不差通过。

### 4. V8 原生 Uint8Array Buffer 重构
- 直接采用 V8 原生 TypedArray，`.slice()` 与 `.subarray()` 视图构建 0 FFI 穿越；
- 数值型 `.fill()` 直接委托 V8 内部 SIMD `memset` 汇编指令；
- 小对象分配复用 8KB Slab 内存池，消除向操作系统申请 ArrayBuffer 的系统调用；
- **基准实测**：Buffer 综合操作耗时 **2.09 ms**（领先 Bun 的 2.62 ms 和 Node 的 2.50 ms）。
