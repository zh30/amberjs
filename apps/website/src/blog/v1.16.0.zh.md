# Amber v1.16.0

v1.16.0 是一次运行时发版，不是营销重置。二进制还是 `amber`。能力边界还是 [Current Scope](https://github.com/zh30/amberjs/blob/main/docs/CURRENT_SCOPE.md)。Node.js Conformance 5.0 仍是 **55/55**。

改了什么：

## Wasm Engine 2.0

`WebAssembly.Memory` 和 V8 `ArrayBuffer` 可以共用 backing store（`new_backing_store_from_ptr`）。大模块可以 mmap。`require('amber:wasm')` 暴露宿主指针。这是 **Preview**。Wasm 仍由 V8 编译；Amber 没有自研 JIT。

## `amber bundle` 和 `amber compile`

都是 **Preview**。

- `amber bundle` 用 oxc 走静态本地 import，模块包进 `__amberjs_require__`，可选 minify。
- `amber compile` 复制宿主 `amber` 二进制，追加 payload 和 `BEE_STANDALONE` trailer。

都不是 webpack、esbuild 或 pkg。

## URL / fetch / ReadableStream

之前的 JS 包装才是瓶颈。v1.16.0 把 URL 解析、HTTP/1.1 keep-alive GET、ReadableStream 队列放到对 JIT 友好的路径上。

Apple M2 Max，2026-09-16，对比 Node v22.22.3：

| 负载 | Amber | Node |
| --- | --- | --- |
| URL + URLSearchParams（20k） | 7.28 ms | 12.54 ms |
| fetch 连续 100 次 GET | 6.51 ms | 17.00 ms |
| ReadableStream 5k chunks | 0.92 ms | 1.16 ms |

Bun 在若干微基准和冷启动上仍然更快。数字在 `benchmarks/`。

## 没变的东西

Amber 不是 Node.js 克隆。覆盖按 API 计。包管理、N-API 和若干 CLI 附加项仍是 Experimental。

安装：

```bash
curl -fsSL https://get.amberjs.com/install.sh | AMBER_VERSION=v1.16.0 sh
```
